# Codex 自然語言回測任務模板

## 背景

你正在協助使用者把自然語言回測需求轉成可執行的本地回測流程。這個專案已具備以下既有能力：

- `update-data`
- `validate-data`
- `run`
- `export-sheets`
- Google Sheets 匯出包含回測設定、績效摘要、淨值資料、網格交易紀錄、儀表板與圖表

你不得修改任何 Python 原始碼。你只能更新既有回測 YAML，並依序執行既有 CLI。

## 使用方式

當使用者輸入自然語言需求時，先把需求整理成明確參數，再執行既有流程。

你必須先確認以下項目：

- symbol
- interval
- start/end
- 策略與策略數量
- 各策略本金
- 槓桿
- 網格上下限
- 網格數量
- 手續費
- Google Sheet ID

若資訊不足或存在影響回測結果的歧義，先停止並詢問，不可靜默猜測。

## 可接受的自然語言輸入範例

- `回測 BTC 最近兩年，現貨、2 倍槓桿做多、10 倍做多網格各投入 500 USDT，網格 60,000～120,000、130 格，結果輸出到 Google Sheets。`
- `幫我做 ETHUSDT 的 1h 回測，從 2023-01-01 到 2024-01-01，現貨和固定 3 倍槓桿各 1000 USDT，最後寫入指定 Google Sheet。`
- `請用近 90 天的 BTC 回測，現貨與網格策略一起跑，先確認資料再回測，再匯出到 Sheets。`

## 參數解析規則

你必須把自然語言解析成明確參數，並在執行前列出：

- `symbol`
- `interval`
- `start`
- `end`
- 策略清單
- 每個策略的 `initial_capital`
- 槓桿倍數
- 網格下限與上限
- 網格數量
- `fee_rate`
- `spreadsheet_id`

解析規則：

- 相對日期必須轉成明確 UTC 日期時間
- `最近兩年`、`最近 90 天` 這類相對日期必須落到明確 `start/end`
- 幣種名稱要正規化成專案接受的 symbol 形式
- 如果使用者說「最近兩年」，你必須明確寫出解析後的 UTC 起訖
- 若使用者沒有指定 interval，使用專案既有預設值，但要在最終回報列出
- 若使用者沒有指定手續費，使用專案既有預設值，但要在最終回報列出
- 若使用者沒有指定本金，不能假設與其他策略相同，必須先確認

## 歧義處理規則

遇到以下歧義時，不得靜默猜測，必須先釐清：

- 相對日期尚未轉成明確 UTC 日期
- 網格上下限是否顛倒
- 使用者提到的是現貨網格還是合約網格
- 槓桿是套用在固定槓桿策略，還是套用在其他策略
- 是否計入 funding rate
- Google Sheet ID 是否存在或是否有效
- 策略本金是否為每個策略獨立
- 網格數量與上下限是否一起指定，且是否合理

安全原則：

- 不得猜測會重大影響結果的參數
- 非關鍵缺省值只能使用專案既有預設值
- 使用既有預設值時，必須在最終回報列出

## YAML 更新規則

你只可以修改既有回測 YAML，不可修改 Python 原始碼。

更新 YAML 時：

- 保留既有格式與專案風格
- 只改與本次回測直接相關的欄位
- 不新增新的核心邏輯
- 不調整策略公式
- 不調整清算模型
- 不調整績效公式

## CLI 執行順序

你必須按下列順序執行，且每一步失敗就立即停止：

```powershell
python -m pytest
python -m src.cli update-data ...
python -m src.cli validate-data ...
python -m src.cli run config/backtest.yaml
python -m src.cli export-sheets --run-dir reports\<RUN_ID> --spreadsheet-id <ID>
```

執行原則：

- 先跑 `pytest`
- 再更新資料
- 再驗證資料
- 再執行回測
- 最後匯出到 Google Sheets

不得：

- 跳過任何失敗
- 用舊報告冒充新結果
- 在前一步失敗後繼續下一步
- 重新下載不必要的大量資料

## 失敗停止條件

以下任一情況都必須停止：

- `pytest` 失敗
- `update-data` 失敗
- `validate-data` 失敗
- `run` 失敗
- `export-sheets` 失敗
- 找不到 `run_id`
- 找不到本地報告目錄
- 找不到 Google Sheet ID
- 任何參數歧義未釐清

停止時必須回報失敗點，不得宣稱成功。

## 禁止事項

你不得：

- 修改策略公式
- 修改清算模型
- 修改績效公式
- 修改資料儲存架構
- 將完整 K 線寫入 Sheets
- 提交憑證
- 自動下單
- 使用舊報告冒充新結果
- 測試失敗後繼續執行
- 猜測會重大影響結果的參數
- 修改 Python 原始碼
- 修改測試
- 新增依賴

## 最終回報格式

回報時必須列出以下內容：

### 1. 實際日期

- `symbol`
- `interval`
- `start`
- `end`

### 2. 實際參數

- 策略清單
- 每個策略本金
- 槓桿
- 網格上下限
- 網格數量
- `fee_rate`
- `spreadsheet_id`

### 3. 資料更新結果

- `update-data` 的輸出摘要
- 是否首次建立或增量更新
- Parquet 路徑
- metadata 路徑

### 4. 驗證結果

- `validate-data` 的輸出摘要
- `VALID` 或 `INVALID`
- error / warning / info 數量
- 主要問題清單

### 5. 回測結果

- `run_id`
- 報告目錄
- 各策略狀態
- 是否清算
- 關鍵績效摘要

### 6. Google Sheets 寫入狀態

- `spreadsheet_id`
- `spreadsheet_url`
- 更新的工作表
- 是否建立儀表板
- 圖表數量
- 是否成功

### 7. 模型假設與限制

- 使用的預設值
- 未能確定但已明確說明的限制
- 任何需要使用者後續確認的事項

## 執行原則

- 先確認，再修改 YAML
- 先驗證，再回測
- 先失敗停止，再往下做
- 只使用既有 CLI
- 不改核心程式
